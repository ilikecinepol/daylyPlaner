# AI Agent V1 — локальный модуль, без платежей

## Что реализовано

- `backend/app/ai/` — отдельные модели, API, провайдер и адаптер к планировщику; `frontend/js/ai.js` — отдельный интерфейс.
- `/api/v1/ai/status`, диалоги, история, удаление истории, отмена запроса, предложения и подтверждения.
- Чтение доступных неархивных задач и их календарных дат, проектов и личных целей. Поиск и день задаются в форме. Контекст ограничен 50 задачами, 20 проектами, 10 целями и 24 000 символами JSON.
- Предложения создать личную задачу или изменить название, описание, статус, приоритет, время и длительность существующей. До подтверждения нет записей в задачи. До пяти предложений на ответ, каждое подтверждается отдельно; это не атомарное массовое изменение.
- Проверка доступа перед запросом и подтверждением, повторная проверка прав на задачи, срок жизни предложения один час, контроль `sync_version`, атомарность записи задачи с состоянием предложения, журнал `ai_change_confirmed`.
- Структурированный план проекта: 1–20 редактируемых этапов, единое подтверждение и атомарное создание нового проекта со всеми этапами как обычными задачами. План можно связать с одной из доступных личных целей; частичное создание исключено транзакцией.
- Для продолжения обсуждения модели передаются до шести последних завершённых пар «пользователь — помощник» текущего диалога. История считается недоверенными данными и удаляется штатной командой удаления диалога.
- Обычные API задач и AI используют общие `create_task_service` / `patch_task_service`. Адаптер передаёт `commit=False`, чтобы предложение и задача фиксировались одной транзакцией. Модель не имеет SQL, shell, HTTP-инструментов или доступа к платёжным функциям.

## Режимы и доступ

По умолчанию `AI_ENABLED=0`. Основное приложение не зависит от ключа или ответа провайдера. Миграция `0015_ai_module` добавляет только собственные таблицы AI и не изменяет таблицы задач/профиля/целей. Отменённые автоматизации не возвращены.

Локальная демонстрация без сети и расходов:

```powershell
$env:AI_ENABLED = "1"
$env:AI_PROVIDER = "demo"
$env:AI_DEMO_ACCESS = "1"
.\.venv\Scripts\python.exe run.py
```

Запускайте после остановки прежнего локального процесса на порту 8000. Demo — не LLM: он показывает выбранные задачи и понимает только проверочные команды `Создай: название` и `Заверши: точное название`. Завершение предлагается только при единственном точном совпадении. Demo-доступ по флагу не действует в production и не перекрывает явно отключённую запись `ai_access`.

Для реального провайдера задайте **в окружении backend** `AI_PROVIDER=openai`, `OPENAI_API_KEY` и явный `AI_MODEL`, поддерживающий Responses API и Structured Outputs. Ключ не передавайте в браузер и не коммитьте. `.env.example` — образец: текущий запуск сам по себе не загружает `.env` в окружение Python.

Для реального провайдера доступ выдаётся вручную, без оплаты:

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m app.ai.access USER_ID enable
# Отключение: та же команда с disable
```

Флаг `AI_ENABLED` также должен быть включён. CLI не выводит секретов и не создаёт платёжных операций. `ai_access` содержит enabled и необязательный expires_at — будущая система подписок сможет управлять этими правами, не меняя AI-модуль.

## Данные, ограничения и стоимость

Адаптер OpenAI использует [Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Запрос отправляется на фиксированный HTTPS-адрес без перенаправлений, с `store=false`, тайм-аутом и ограничением выхода 2000 токенов. `store=false` не следует трактовать как гарантию отсутствия любого хранения данных провайдером; перед реальным запуском нужно отдельно согласовать условия обработки данных.

Отправляются запрос пользователя, минимальные поля выбранных задач, названия проектов и краткие личные цели. Контекст проверяется сервером; описания записей рассматриваются как недоверенные данные. Ответы отображаются текстом, без HTML/Markdown-ссылок от модели. Источники — кнопки реальных задач; при утрате доступа к источнику старый ответ скрывается. История хранится локально в БД, но **не передаётся модели в V1**: каждый запрос самостоятельный. Внешние события Google Calendar пока не входят в контекст.

`AI_USER_DAILY_LIMIT=20`, `AI_GLOBAL_DAILY_LIMIT=100` ограничивают число попыток в сутки UTC, включая ошибки и отмены. Квота резервируется атомарно до вызова модели; повтор с тем же request_key не делает новый вызов. Число входных/выходных токенов сохраняется для успешно обработанных ответов. Лимиты запросов/контекста/выхода ограничивают расход, но не являются точным денежным бюджетом; реальные расходы и тариф нужно проверить перед включением провайдера. Реальных платных запросов при внедрении не выполнялось.

Отмена не гарантирует прекращения уже отправленного внешнего запроса и списания у провайдера: она не позволяет применить его результат. При удалении диалога удаляются предложения, очищаются запросы, ответы и источники; технические записи попыток и суточные счётчики сохраняются для защиты лимитов. Применённые задачи и их аудит не удаляются. При выключении доступа пользователь может читать/удалять свою историю, но не отправлять новые запросы и не подтверждать предложения.

## DeepSeek

Добавлен отдельный адаптер `backend/app/ai/deepseek.py`. Для переключения backend:

Самый безопасный локальный запуск — готовым сценарием, который запрашивает ключ скрыто и держит его только в окружении работающего процесса:

```powershell
.\scripts\run-local-deepseek.ps1
```

Сначала остановите прежний процесс на порту 8000. По умолчанию сценарий включает `deepseek-v4-flash` и локальный доступ для аккаунтов без явной записи `ai_access`. `AI_LOCAL_ACCESS` намеренно игнорируется в production. При остановке сценарий удаляет ключ из своего окружения; на диск ключ не записывается.

Ручной эквивалент:

```powershell
$env:AI_ENABLED = "1"
$env:AI_PROVIDER = "deepseek"
$env:DEEPSEEK_MODEL = "deepseek-v4-flash"
$deepseekSecret = Read-Host "DeepSeek API key" -AsSecureString
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new("", $deepseekSecret).Password
Remove-Variable deepseekSecret
```

Затем выдайте доступ пользователю командой из раздела выше и перезапустите приложение в этом же терминале. Не запускайте второй экземпляр на занятом порту. Переменные окружения не сохраняются после закрытия терминала. Ключ нельзя отправлять в чат, помещать в клиентский код или коммитить. Для смены ключа того же сервиса заменяется только `DEEPSEEK_API_KEY` и перезапускается backend; модель меняется независимо через `DEEPSEEK_MODEL`. Если модель не указана, выбирается `deepseek-v4-flash`. Ключ другого провайдера автоматически не подставляется.

Используется фиксированный адрес `https://api.deepseek.com/chat/completions`, `max_tokens=2000`, `thinking.type=disabled`, тайм-аут и запрет перенаправлений. Формат JSON настроен по [документации DeepSeek](https://api-docs.deepseek.com/guides/json_mode/); отключение thinking — по [описанию режима](https://api-docs.deepseek.com/guides/thinking_mode/). JSON-режим не заменяет проверку схемы: пустые, оборванные и невалидные ответы отклоняются сервером, как и неожиданные вызовы инструментов. Автоматических повторов и переключения на другого провайдера нет. Ключ, сырой ответ с ошибкой и данные запроса не выводятся в клиентские ошибки.

Проверки адаптера выполнялись с подставным HTTP-клиентом без сети. Живые вызовы, качество модели на русском и доступность оплаты пока не проверены. До явной настройки ключа локальное приложение остаётся в demo-режиме. Не отправляйте реальные личные данные в первых пробах — используйте отдельный тестовый аккаунт и вымышленные задачи.

## Следующие расширения

Реальная оценка качества выбранной модели; создание задач в уже существующем проекте; добавление, удаление и перестановка этапов непосредственно в редакторе; зависимости между задачами; внешние календарные события; денежный бюджет с актуальной стоимостью модели. Платежи, автоматизации, AI-исполнитель и автономные действия не входят в этот этап.
